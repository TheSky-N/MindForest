# 1 设计初稿

## 1.1 核心功能设计

### 1.1.1 以导图的形式组织对话

核心是将与 AI 对话的各个分支以树状图的形式呈现。Explore 里还套了一层卡片，一张卡片里可以有多个对话，每个对话都可以分出分支来延伸。这个理念与卢曼的原教旨卡片盒笔记系统自然延伸笔记的方式、XMind 思维导图组织主题的方式都很近似。

以“主题卡片”为基本单位，每张卡片中可以有一个或多个 AI 对话。

每个项目以唯一的“中心主题”为核心。新建主题卡片分为两类：

1. 新建子主题；
2. 新建分支主题。

> [!NOTE]
> 每个主题都可以横向“发散”关联到另一个新的“自由主题”上，这个新的主题不继承原本的上下文，只关联原本对话的主题，用以发散出新的主题和分支结构。自由主题与原主题处于同一层级，并以虚线连接。

可视化方式：将每一张卡片缩小为一个小的实体（如圆形），并参考 XMind 思维导图或树状图进行组织。鼠标悬停时，显示当前实体代表的卡片的主题。

### 1.1.2 思想自然地延伸

在主题卡片中进行对话时，AI 自动标注对话中可能不熟悉地表达和术语，点击之后即可查看其介绍或解释；若仍然存在不懂处，可从此快速创建子卡片，从而继续深挖。若人为选中任意文本或公式，也可以进行相同的操作。

### 1.1.3 精确地管理对话

- 可以随时选中并引用 AI 回答中的任意部分。
- 每个回答均可重新生成。
- 每条消息均可删除或修改。

### 1.1.4 思维森林

可人为选中任意文本或公式进行批注，还可以调用 AI 评价自己写出的批注内容，并据此修改，直到没有问题为止。如果没有问题，就可以将其作为一颗种子，种在“思维森林”中。

当之后 AI 再次回答相关问题时，会优先以此作为锚点进行讲解。

## 1.2 技术要求

1. 默认采用 Markdown 渲染 AI 输出的文本。
2. 至少兼容 Windows 和 Fedora Linux 双端。
3. 性能尽量好。

## 3.1 v0.1 

### 3.1.1 v0.1.0 用主题卡片树来管理 AI 对话

把与 AI 的对话组织成**主题卡片树**：每个主题是一张卡片，可以长出**子卡片**（继续深入）与**分支卡片**（平行尝试），并随时沿树切换、追溯。

#### 3.1.1.1 核心特性

- **卡片树对话**：子卡片自动携带父卡片摘要作为背景；分支卡片创建时冻结继承上下文；右侧 d3-hierarchy + React Flow 可视化卡片树，点击节点切换，支持全屏
- **流式对话**：OpenAI 兼容接口（自定义 Base URL / 模型 / 温度 / API Key），SSE 流式输出、30ms 批量渲染；可随时停止并保留已生成内容
- **精确消息管理**：引用任意回答片段（自动注入模型上下文）、编辑用户消息（级联删除后续轮次，分支点受保护）、重新生成并切换多版本、删除任意轮次
- **渲染**：Markdown / GFM / KaTeX 公式 / Shiki 代码高亮（按需加载语言）、长对话虚拟滚动
- **上下文装配**：token 预算截断；子卡片自动使用父卡片摘要（按阈值后台刷新）；分支使用冻结快照，来源卡片变化不影响已建分支
- **本地优先**：SQLite 存储于应用数据目录；API Key 经系统密钥环（safeStorage）加密，密钥环不可用时降级为仅会话保存

## 3.2 v0.2

### 3.2.1 v0.2.0 取消卡片逻辑，直接构建主题对话树

#### 3.2.1.1 更新目标

- 彻底抛弃原本以卡片作为节点的逻辑，改用对话为核心，一轮对话作为一个节点。“卡片树”更名为“主题对话树”。
- 每向 AI 发送一条消息，就是在创建一个子节点。分支操作和上下文逻辑都变得极为直观。
- 将主题对话树上的鼠标左键操作分为单击和双击，单击代表选中该节点/预览，双击则是进入并从该节点继续。
- 以“主题节点簇”取代“主题卡片”：可在图上拖拽框选或点击选择多轮对话，将它们在图上折叠到同一个“主题节点簇”之中，但实际上不改变对话分支的结构。根本规则只有一条：没有线条连接的对话节点不能归到一个主题中。
- 主题之间不能重叠或嵌套。
- 原本的卡片重命名和 AI 总结主题操作，继承到现在的“主题”上。
- 同一层级当中，可任选一个作为“主分支”，主题对话树布局围绕这个“主分支”进行。如，主分支路径高亮加粗，或降低除主分支和当前所在分支以外部分的透明度。
- 为对话节点添加“归档”操作，归档后的节点自动折叠所有子节点，并在图上以低透明度显示。若想再次打开，需要在图上右键并“取消归档”。取消归档后，归档节点的子节点的折叠状态恢复到未归档之前。

#### 3.2.1.2 更新内容

这是一次架构级更新：**取消卡片逻辑，对话本身成为树**。每一轮问答就是一个节点，分支、上下文与主题聚合都围绕对话展开。

- **对话即树**：向 AI 发送一条消息 = 在所选节点下创建一个子节点；分支不再需要专门操作，从任意历史节点继续即可
- **单击 / 双击**：单击节点预览整条对话路径（输入框禁用并提示），双击进入并从该节点继续；也可用「进入并继续」按钮
- **主题节点簇**：在图上多选（Ctrl/Cmd+点击）或框选（Shift+拖拽 / 选择模式）多轮对话，折叠为一个主题；未连线的选择会自动补全中间节点并提示。主题之间不允许重叠或嵌套
- **主分支**：同层可任选一个节点设为主分支；主路径连线加粗高亮，非主分支且非当前路径的部分降低透明度
- **归档与折叠**：归档节点会隐藏其整棵子树并变暗显示，取消归档后恢复原先的折叠状态；折叠状态独立保存
- **主题的 AI 总结**：创建主题时自动生成标题与摘要（也可右键手动触发），重命名与 AI 总结延续到主题上；「后台任务模型」可单独指定
- **链摘要（长对话质量保障）** ：祖先链超阈值时后台生成边界摘要并在分支间复用，避免深链早期背景被预算截断
- **回收站**：删除节点为软删除，可在回收站恢复或彻底删除；级联删除有明确提示
- **重新生成**：每次重答创建一个带 ​`turn_group_id` 的平行节点，可切换/同组同步编辑

### 3.2.8 v0.2.5-alpha-1 预发布：模型能力、附件、搜索与可靠性

> 发布日期：2026-10-19。这是 v0.2.5 的首个预发布版本，覆盖 3.2.6、3.2.7 的目标，并额外完成四项日常效率与数据可靠性改进。

#### 3.2.8.1 模型能力

- **能力标签**：模型配置新增「推理 / 视觉 / 上下文窗口 / 最大输出」，上下文预算按模型窗口动态计算（窗口的 20%，限制在 4k–24k）。
- **Provider 预设**：DeepSeek、OpenAI、OpenRouter、Ollama、Moonshot、通义千问、智谱、自定义 OpenAI 兼容接口；选择预设会自动填入 Base URL、模型与能力。
- **思考强度**：按厂商转换为 `reasoning_effort`（OpenAI）、`reasoning.effort`（OpenRouter）、`enable_thinking`（通义千问）、`thinking`（智谱）；DeepSeek reasoner 无需额外参数。
- **思考内容**：解析 `reasoning_content` / `reasoning` / `thinking` 的流式增量；支持默认展开、折叠、隐藏，折叠时只渲染设置的行数；思考内容不回传上下文。
- **重试与退避**：对 408/409/429/5xx 与网络错误自动重试，最多 2 次，遵循 `Retry-After`。

#### 3.2.8.2 附件与多模态

- 单条消息最多 8 个附件，单个上限 12MB。
- 图片附件以多模态片段发送给启用「视觉」的模型；未启用视觉时禁止上传图片。
- 文本类文件（txt/md/json/csv/代码等）自动提取 UTF-8 内容注入上下文，单文件上限 20 万字符。
- 附件元数据写入 `attachments` 表，文件存放于应用数据目录的 `attachments/`；重新生成节点会复制原节点的引用与附件。

#### 3.2.8.3 搜索、草稿与视口

- **全文搜索**：SQLite FTS5 `trigram` 中文索引，覆盖标题、提问、回答；三字以下查询回退 `LIKE`；结果带项目名、命中字段与高亮片段。
- **命令面板**：`Ctrl+P` 搜索所有项目并跳转节点，同时提供新建标签页、设置、切换主题、立即备份、打开备份目录等快捷操作。
- **标签页草稿**：每个标签页独立保存输入草稿，切换、重开标签页后恢复。
- **树视口**：每个标签页独立记住缩放/平移；新增「定位当前节点」；不再在每次节点变更时强制 `fitView`。

#### 3.2.8.4 数据可靠性与桌面体验

- **自动备份**：启动时若 24 小时内无备份则自动创建，保留最近 12 份；设置页支持立即备份、查看列表、一键恢复（恢复前自动创建 `pre-restore` 备份，成功后自动重启）。
- **单实例**：重复启动聚焦已有窗口，避免多进程写同一数据库。
- **窗口状态**：记住窗口大小、位置与最大化状态。
- **导出增强**：Markdown 导出包含思考过程与附件名；JSON 导出包含附件元数据。

#### 3.2.8.5 已知限制

- 仅支持 OpenAI 兼容 `/chat/completions`，未适配 Anthropic / Gemini 原生协议。
- 附件文本提取以 UTF-8 文本为主，PDF / Office 解析尚未实现。
- Windows 构建与自动更新尚未验证。
- 预发布版本的数据格式可能继续调整，升级前请先备份。
